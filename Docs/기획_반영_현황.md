# 기획 반영 현황

기획 원본(구글 스프레드시트 "킹덤러쉬" + 손그림 경로 스케치)이 구현에 반영됐는지 추적하는 문서.
갱신 시점: 2026-08-08

기획 원본 링크는 `스프레드시트 링크.md`. 시트가 원본이고, 코드의 `RushRewardCatalog`가 ID 기준으로 에셋을 동기화한다.
시트가 갱신되면 이 문서의 "최근 추가된 기획"에 항목을 먼저 적고, 반영이 끝나면 적용됨으로 옮긴다.

## 최근 추가된 기획

| 항목 | 출처 | 상태 |
|---|---|---|
| C13 연발 장전 (영웅) | 보상 시트 | 적용됨 |
| C14 처형 예포 (전설) | 보상 시트 | 적용됨 |
| C15 행운의 부적 (전설) | 보상 시트 | 적용됨 |
| 경로 4루트 구성 (시작 2곳 x 종료 2곳) | 손그림 스케치 | 미적용 |

## 적용됨

### 보상 카드

| ID | 이름 | 효과 | 구현 위치 |
|---|---|---|---|
| C13 | 연발 장전 | 공격당 15% 확률로 추가 발사체 1발 (피해 150%, 소범위 광역) | `RewardEffectType.BonusProcShot` / `Tower.TryProcShot` |
| C14 | 처형 예포 | 처치 시 주변 적에게 추가 발사체 3발 (각 피해 60%) | `RewardEffectType.BonusOnKillShot` / `Tower.FireOnKillShots` |
| C15 | 행운의 부적 | 확률 판정 실패 시 1회 재굴림 (20% -> 36%) | `RewardEffectType.LuckReroll` / `Luck.Roll` |

나머지 54종은 P05를 제외하고 전부 활성 상태다. 수치는 전부 에셋에 있고 Balance Board(Rush > Balance Board)에서 조정한다.

### C13/C14 전환에 따른 구조 변경

기존에 타워 데이터(`AttackExtras`)에 기본 켜짐인 개발자 옵션으로 있던 추가 발사를 보상 구동으로 바꿨다.

- `AttackExtras`의 값은 이제 **연출 파라미터**(프리팹/궤적/속도/탐색 반경)가 본체다.
- Enabled/Chance/Count/DamageScale은 보상 없이 연출을 확인하기 위한 **개발자 강제 켜기**이며 기본 꺼짐이다.
  타워 에셋 4종의 토글도 꺼짐으로 내렸고, 셋업 재베이크도 꺼짐으로 굳힌다.
- 강제 켜기와 보상이 동시에 있으면 확률은 독립 결합하고, 발수/피해 배율은 큰 쪽을 쓴다.
- 조작 위치는 Stage Command Center의 "추가 발사" 섹션.

## 미적용

### 경로 4루트 구성

손그림 기준 구성이다. **시작 지점 2곳에서 각각 두 방향으로 갈라져 종료 지점 2곳으로 들어가는 총 4개 루트**다.

| 루트 | 시작 | 종료 | 스케치 색 |
|---|---|---|---|
| A1 | 시작 A (좌상단) | 종료 1 (우상단) | 녹색 |
| A2 | 시작 A (좌상단) | 종료 2 (우하단) | 갈색 |
| B1 | 시작 B (좌하단) | 종료 2 (우하단) | 빨강 |
| B2 | 시작 B (좌하단) | 종료 1 (우상단) | 파랑 |

네 루트는 맵 중앙에서 서로 교차하며 크게 돌아간다. 타워 슬롯은 교차 구간에 몰려 있어
한 슬롯이 여러 루트를 동시에 덮는 배치가 나온다 (사거리 가치가 루트 수에 비례).

현재 구현은 **단일 경로**다.

- `PathRoute` 1개(자식 Transform이 웨이포인트), `StageController._path`가 단일 참조로 들고 있다.
- `WaveSpawner`는 `_path.GetPoint(0)` 한 곳에서만 스폰한다.
- `Monster`는 이미 생성 시 `PathRoute`를 주입받으므로, 루트별 인스턴스를 넘기는 것 자체는 가능하다.

필요한 작업:

1. 씬에 `PathRoute` 4개 배치 + 시작/종료 마커 정리. 셋업(`RushSetupActions.SetupPath`)이 단일 "Path" 오브젝트를 찾는 구조라 다중 루트로 확장 필요.
2. `StageController`/`WaveSpawner`의 경로 참조를 배열로 확장하고, 웨이브 구성에 루트별 물량 분배를 추가.
3. 경로 비주얼 베이크(`BakePathVisual`)와 검증(`ValidateScene`의 PathRoute 체크)을 루트 수만큼 반복하도록 수정.
4. 종료 지점이 2곳이 되므로 도달 처리(`HandleMonsterReachedExit`)가 어느 종료인지 구분할 필요가 있는지 결정. 생명 감소만 한다면 공통 처리로 충분하다.
5. 웨이브 예산이 루트 4개로 흩어지면 체감 난이도가 크게 떨어지므로 물량/타워 슬롯 수 재조정 필요.

## 부분 적용 (동작하지만 기획 문구보다 범위가 좁음)

- **C13/C14가 병영 타워에는 발동하지 않는다.** 시트의 대상 타워는 "공통"이지만, 병사 근접 공격은 발사체 경로를 타지 않는다.
  시트에서 대상을 궁수/마법사/포병으로 좁히거나 조건 칸에 명시하는 편이 정확하다.
- **화염 장판 등 지속 피해로 죽인 적에는 C14가 붙지 않는다.** 발사체 착탄과 죽음의 광선 처치에만 연결돼 있다.
  지속 피해 쪽에 처치 감지 훅을 새로 넣어야 하며, 틱마다 발동하면 폭주 위험이 있어 보류했다.
- **C15는 즉사 판정과 보상 카드 추첨에는 적용되지 않는다** (시트 조건에 명시된 대로).

## 밸런스 미조정

`4.클라이언트 아키텍처 설계서.html` 10장 참조. 추가 발사가 보상으로 넘어가면서 상시 적용은 아니게 됐지만,
C13 + C14가 같이 모이는 판의 후반 강도는 따로 확인해야 한다.
