# 기획 반영 현황

기획 원본(구글 스프레드시트 "킹덤러쉬" + 손그림 경로 스케치)이 구현에 반영됐는지 추적하는 문서.
갱신 시점: 2026-08-09 (시트 11장 재수신 후 diff)

기획 원본 링크는 `스프레드시트 링크.md`. 시트가 원본이고, 코드의 `RushRewardCatalog`가 ID 기준으로 에셋을 동기화한다.
시트가 갱신되면 이 문서의 "최근 추가된 기획"에 항목을 먼저 적고, 반영이 끝나면 적용됨으로 옮긴다.

### 시트 내부에서 값이 엇갈리는 항목

정리되기 전까지는 아래 선택을 유지한다.

- 조기 소환 보너스: 구성예산 시트는 15%, 스폰 시스템 시트는 "예산의 0~8%". 현재는 15%를 쓴다.
- 아키타입 등장 확률: 스폰 시스템 시트의 단일 표(J열)와 구성예산 시트의 웨이브 구간별 표가 다르다.
  구간별 표(7~12 / 13~18 / 19~23)를 원본으로 삼아 구현했다.
- 스폰 시스템 시트의 아키타입 요약 표(마릿수 / 간격)는 같은 시트의 배치 규칙을 그대로 계산한 값과 맞지 않는다.
  예를 들어 정예 1 W7은 "19마리 / 5.45초"인데 예산 배분 40/60과 단가로 계산하면 27마리 / 11배치가 나온다.
  시트 자신이 "시간 간격은 대충 설정해서 두셔도 됩니다"라고 적어 두었으므로 규칙 쪽을 원본으로 삼았다.
- 24웨이브 시트의 정규 예산은 3,815인데 구성예산 시트의 24웨이브 예산은 3,905다. 예산표 쪽을 썼다.
  그 여파로 추가 스폰 예산이 시트에 적힌 1,905가 아니라 1,953(3,905의 50%)이 된다.
- 24웨이브 시트의 "시간 경과 압박" 표는 배수 2.0에서 출발하는데, 바로 위 문장은 "시작 배수는 3.91"이다.
  표 쪽을 원본으로 삼았다 (2.0 -> 2.1 -> 2.2 …).
- 고정 구간의 출구가 두 시트에서 다르다. 구성예산 시트는 "1번 / 1번 / 2번 / 1번 / 2번 / 1,2번"인데
  스폰 시스템 시트의 경로 배정(A1 / A1·A2 / A1·B1 / B1·B2 / 전체 / 전체)과 맞지 않는다.
  경로 ID가 명시된 스폰 시스템 시트를 원본으로 삼았다.

## 적용됨

### 타워 시트 전체 반영 (2026-08-09)

그동안 타워는 시트의 **가격표만** 반영돼 있었고 공격력·공격주기·사거리는 손으로 맞춘 값이었다.
시트 값으로 재베이크하면서 타워 DPS가 대략 2배가 됐다 (적 스탯은 원래부터 시트값이었다).

- 공격력은 시트의 최소~최대 중앙값을 쓴다. 범위 시스템이 없어서이고, 생기면 보상 P05와 함께 살아난다.
- 공격주기는 시트값 그대로 (궁수 0.5 / 명사수 0.25 / 총포상 1.0 / 마법 1.0 / 흑마 1.5 / 환술 0.75 / 포병 1.5 / 병영 1.0).
- 사거리와 폭발 반경은 시트가 원작 화면 픽셀 단위(100~320)라 `SheetRangeScale`(1/32)로 환산한다.
  계수는 시트 20개 항목의 평균이 기존 게임 값 평균(4.72)과 맞도록 잡았다. 시트의 상대 비율은 그대로 살고,
  맵 대비 전체 스케일은 이 상수 하나로 조정한다. 궁수가 3.75 -> 10까지 크게 벌어지고 마법/포병은 5에서 평평해진다.
- 병영 유닛 체력 60/110/170/280/220, 공격력 3~5 / 5~8 / 8~11 / 10~15 / 15~20으로 시트값을 넣었다.
- 광역 감쇠를 `TowerLevelStat.SplashEdgeDamage`로 새로 넣었다. 폭발 중심 100%에서 가장자리 값까지 선형 감쇠한다
  (포병 1·2단계 60%, 3단계 75%, 용의 숨결포 감쇠 없음, 장사정포 75%). 그동안 반경 안 전원이 100%를 맞고 있었고,
  용의 숨결포 분기의 "광역 감쇠 소멸" 정체성이 아예 없었다.

시트에 칸이 없어 **그대로 둔 것** (지우면 밸런스가 크게 흔들려 기획 판단이 필요하다):

- 마법 타워의 기본 감속(25~40%). 시트 타워 표에 감속 칸이 없고, 보상 D01/B3B/C11의 조건이
  "감속원이 없으면 무효"라 기본 감속은 없는 쪽이 시트 의도로 읽힌다. 그래도 지우면 유일한 상시 군중제어가 사라진다.
- 포병의 `ArmorPierce = 0.5`(물리 방어 50% 무시). 보상 P04가 "20% 확률로 물리 방어 무시"인 것과 겹친다.

### 웨이브 수치 재베이크 (2026-08-09)

전부 `RushSetupActions`의 상수/베이크 코드에 있으며, 셋업 재실행 시 시트 값으로 덮어쓴다.

- 시작 골드 300 -> 350. 이후 초반 건설 여유를 주려고 550으로 다시 올렸다 (2026-08-10, 시트 외 조정).
- 웨이브 예산 24개를 시트 B열로 교체 (160 ~ 3905, 23웨이브 누적 32100).
- 적 스탯 배수를 웨이브당 복리(1.06)에서 시트의 계단식으로 교체: 1~6 = 1.0, 7~12 = 1.25, 13~18 = 1.5, 19~24 = 2.0.
- 웨이브 간격 45초 -> 80초 (시트: 스폰 60초 + 대기 20초). 스폰을 60초 안에 끝내는 배치 규칙은 아직 없다.
- 고정 구간(1~6웨이브) 마릿수를 새 예산에 맞춰 다시 계산하고, 시트의 고정 구간 경로를 `RouteIds`로 넣었다
  (1: A1 / 2: A1·A2 / 3: A1·B1 / 4: B1·B2 / 5~6: 전체).
  경로 가중치도 `RouteWeights`로 시트값을 넣었다 (2~3웨이브 50/50, 4웨이브 60/40, 5웨이브 30/20/30/20, 6웨이브 균등).
  순번 분배 대신 배치마다 이 가중치로 뽑는다. 6웨이브 보스는 `BossRouteId = "A1"`으로 고정이고,
  12/18웨이브 보스는 그 웨이브가 쓸 수 있는 경로 중 무작위다 (시트: 중간보스 3종).
- 중간 보스 최종 스탯이 시트값(체력 450 / 2000 / 10000, 킬 보상 510 / 970 / 1850, 이동속도 0.5)이 되도록
  에셋 값을 웨이브 배수로 나눠 넣었다. 방어는 공성 책사 기준(물리 2단계 / 마법 2단계).
- 막증축 스킬 18종의 총액을 시트 J열로 교체. 수치 변경 3건:
  장비 개조 +15/20/25 -> +4/7/10, 신성한 강타 15% 고정 -> 10/15/20%(피해 2배 고정),
  신성한 의무 쿨타임 60초 고정 -> 60/45/30초. 뒤 두 건은 `Soldier`의 하드코딩을 스킬 정의 참조로 바꿨다.

### 1웨이브 수동 시작 (2026-08-10, 시트 외 조정)

1웨이브만 카운트다운을 없애고 플레이어가 시작 버튼을 눌러 내보낸다. 초기 타워를 다 짓고 시작하라는 의도이며,
타이머가 없으니 "앞당길 시간"도 없어 조기소환과 보상 제시가 둘 다 붙지 않는다.

- `StageController.AwaitingFirstWave`가 켜져 있는 동안 다음 웨이브 카운트다운이 흐르지 않는다 (보스 게이트와 같은 방식).
- `StageController.StartFirstWave`는 보너스 골드 없이 `StartWaveNow`로 직행한다. 조기소환이 아니라 시작이다.
- `CanCallEarly`가 `WaveNumber == 0`에서 false라 조기소환 보너스는 어떤 경로로도 지급되지 않는다.
- `GameHUD`는 같은 자리의 버튼을 1웨이브에서 "웨이브 시작", 2웨이브부터 "조기소환 +NG"으로 쓴다.
- 기존 `StageData.FirstWaveDelay`(25초)는 쓰는 곳이 없어져 필드째 제거했다. `WaveInterval`(80초)은 2웨이브부터 그대로다.
- 카드 제시는 `FirstRewardWave = 2`가 막는다 (에셋이 1로 낡아 있어 1웨이브에 뜨던 것을 함께 고쳤다).

### 아키타입 배치 스폰 (2026-08-09)

7~23웨이브의 스폰이 "예산 남는 동안 1마리씩 무작위"에서 시트의 배치 구조로 교체됐다.
표는 `StageData.Archetypes`에 있고 `RushSetupActions.BuildArchetypes`가 시트값을 굽는다.

- 아키타입 6종(개떼 1 / 개떼 2 / 정예 1 / 정예 2 / 기동 / 짬). 구성원과 예산 배분 비율, 예산 계수,
  구간별 등장 확률, 경로 수 확률을 각각 갖는다. 짬은 구성원을 비워 `RandomPool` 전체를 균등 배분한다.
- 제약 전부 구현: 같은 아키타입 2연속 금지, 개떼 1 최소 4웨이브 간격(`MinGap`),
  정예 2는 13웨이브 이후(`MinWave`), 보스 직후 7·13·19는 개떼 2와 짬만(`AllowedAfterBoss`).
- 예산 이월: 계수 적용 후 배분/단가로 소진되지 않은 잔액을 다음 웨이브 예산에 더한다.
  배분 후 잔돈은 가장 싼 구성원으로 한 번 더 채워 예산 상한을 최대한 맞춘다.
- 배치: 크기는 `MonsterData.BatchSize`(민병 4 / 중보병 2 / 라이더·정찰병 3 / 마법사·백인대장 1).
  배치 간 간격 = `SpawnWindow(60초)` / 총 배치 수, 배치 내부는 0.35초.
  간격이 2초 미만이면 같은 적의 배치를 둘씩 합쳐 크기를 2배로 만들고 재계산한다 (최대 2회,
  마법사·백인대장은 `AllowBatchGrowth = false`로 제외).
- 경로: 웨이브마다 사용할 경로 수를 아키타입 확률표로 뽑고, 그만큼 무작위로 골라 1~10 정수 난수를
  가중치로 준다. 배치마다 이 가중치로 경로를 뽑는다.
- 씬 검증에 아키타입 검사를 추가했다 (구간별 후보 2종 미만, 배분 합이 1이 아님, 짬 아키타입 누락).

알려진 편차: 자동 조정으로 커진 배치는 내부 스폰 시간(0.35초 x 배치 크기)이 배치 간 간격보다 길어진다.
이때는 스폰 구간 60초를 지키는 쪽을 택해 배치 내부 간격을 `간격 / (마릿수 - 1)`로 눌러 담는다.
간격 계산식 자체가 60초를 전제로 하므로 0.35초 고정보다 구간 길이가 우선이라고 봤다.

### 중간 보스 3종 배정과 처치 게이트 (2026-08-09)

- `StageData.BossArchetypes`에 3종(돌격대장 0.80 / 타락한 사제 0.90 / 공성 책사 1.00)을 굽는다.
  방어 배분과 체력 배율만 종류가 정하고 공격력·킬 보상은 웨이브 슬롯 값을 그대로 쓴다 (시트 기준).
- `WaveSpawner`가 판 시작 시 3종을 무작위 순열로 세워두고, "몇 번째 보스 웨이브인지"로 배정을 고른다
  (`BossArchetypeFor`). 스폰 실패나 보스 항목 수가 배정을 밀지 않게 스폰 횟수 카운터를 쓰지 않는다.
  한 판에 셋이 모두 나오고 순서만 매판 달라진다 (6가지 순열).
- 보스는 단일 경로 고정이다. 등장할 때 그 웨이브가 쓸 수 있는 경로 중 하나를 무작위로 뽑는다.
- 보스 처치 게이트: 보스 웨이브에서 보스가 처리되기 전까지 다음 웨이브 카운트다운이 멈추고
  조기소환도 막힌다. 통과당해도 게이트는 풀린다 (처치하지 못했을 뿐 웨이브는 끝난 것으로 본다).
  HUD가 "보스를 처치해야 다음 웨이브로 넘어간다"로 표시한다.
  프리팹 누락 등으로 보스가 아예 등장하지 않으면 `ReleaseStuckBossGate`가 게이트를 풀고 경고를 남긴다.
- 보스 이름은 `Monster.DisplayName`으로 종류 이름("돌격대장")이 표시된다.
  데이터 이름("중간 보스 1")은 웨이브 슬롯 이름이라 매판 달라지는 정체를 못 보여준다.

### 24웨이브 최종 보스전 (2026-08-09)

- `Monster_FinalBoss`(반란군 우두머리): 최종 체력 30000, 공격력 110, 이동속도 0.5, 킬 보상 0,
  통과 시 라이프 100 차감. 웨이브 시작과 동시에 등장한다.
- `WaveData.IsFinalWave`가 켜지면 정규 스폰(예산 3905) 뒤에도 30초마다 추가 스폰이 계속된다.
  추가 예산은 정규 예산의 50%, 스탯 배수는 `기본 배수 x (1 + 0.05 x 횟수)`로 누적된다
  (2.0 -> 2.1 -> 2.2 …, 시트의 시간 경과 압박 표와 같다).
- 24웨이브는 정규 스폰과 추가 스폰 모두 짬 아키타입 고정이고 예산 계수를 적용하지 않는다
  (시트: 잡졸 구성 = 짬 아키타입, 6종 전부). 아키타입 계수를 또 곱하면 추가 예산 50%가 42.5%가 된다.
- 최종 보스 스폰이 실패하면(프리팹 누락) 추가 스폰을 시작하지 않는다.
  처치로만 끝나는 웨이브라 보스가 없으면 승리도 패배도 나올 수 없다.
- 최종 보스를 처치하면 잡졸이 남아 있어도 즉시 승리하고 추가 스폰이 끊긴다 (`WinByFinalBoss`).
  무한 스폰이 계속되는 동안은 "모든 적 제거" 승리 조건이 성립할 수 없으므로 이 경로가 유일한 승리다.

### 등장 / 교전 방향 처리 (2026-08-09)

- `Monster`가 스폰 시 좌우 레인 오프셋(±0.45)과 진행 거리 지터(0~0.8), 요 지터(±25도)를 뽑는다.
  레인 오프셋은 경로 접선의 수직 방향으로 적용되며 프로브까지 같이 밀리므로 행군 중에도 유지된다.
  위치를 순간이동시키는 곳(스폰/넉백/귀환)은 전부 `PathPosition`을 거친다.
- 저지당한 몬스터는 `FaceBlocker`로 자기를 붙잡은 병사 쪽을 바라본다.
- `Soldier`는 소환 시 병영 반대쪽을 즉시 바라보고, 접근·교전 중에는 표적을, 복귀 중에는 진행 방향을 바라본다.
  몸체가 표적을 향하므로 찌르기 연출 방향은 로컬 정면으로 바뀌었다.
- 타워는 아직 표적 쪽으로 돌지 않는다.

### 병영 랠리 포인트 지정 (2026-08-09)

시트(병영 시트)의 "병영 클릭 - 랠리 포인트 아이콘 클릭 - 배치할 위치 클릭"을 넣었다.
그 전까지는 `ComputeRallyPoint()`가 타워에서 가장 가까운 경로 지점에 고정했고 플레이어가 옮길 수단이 없었다.

- 건설된 병영을 고르면 라디얼 왼쪽에 깃발 버튼이 뜬다 (`IconGlyph.Flag`). 병영이 아닌 계열에서는 숨는다.
- 누르면 라디얼이 잠시 접히고 배치 가능 거리 원이 뜬다. 지면을 찍으면 확정, 우클릭/ESC로 취소한다.
- 찍은 위치는 배치 가능 거리로 자른 뒤 가장 가까운 루트 위로 스냅한다.
  길에서 떨어진 곳에 세우면 아무것도 막지 못하므로 경로 스냅은 유지했다.
- 배치 가능 거리 = 병영 `Range`(시트 100 환산) x `RallyRangeMul`. 보상 E06(전방 전개)이 여기 붙는다.
- 이미 나가 있는 병사도 같이 옮긴다. 붙잡고 있던 적은 놓아준다 —
  계속 붙들고 있으면 전선이 옛 자리에 남는다.

### 병사 체력 재생 (2026-08-09, 시트 외 추가)

시트에 없는 항목이다. 병사가 **상시** 체력을 회복한다 (교전 중에도 멈추지 않는다).
충원(병사별 10초, 기사단 13초 재소환)이 전선 회전을 담당하고, 이건 병사가 그 사이 버티게 하는 쪽이다.

`TowerLevelStat.SoldierRegenPerSecond`에 있고 단계별로 최대 체력의 3%/초를 굽는다
(1.8 / 3.3 / 5.1 / 기사단 8.4 / 용병단 6.6). 상시 회복이라 회복량이 적 공격력을 넘으면 전선이 영구히 버틴다.
민병 6, 중보병 10, 백인대장 35와 견줘 잡은 값이고, 세면 이 값을 먼저 내리면 된다.

### 병사 충원을 자리별로 분리 (2026-08-10)

충원 대기가 병영당 하나뿐이라, 병사가 죽을 때마다 그 타이머가 처음부터 다시 돌았다.
앞서 죽은 병사의 충원이 뒤에 죽은 병사 때문에 계속 뒤로 밀려, 압박받는 전선일수록 병사가 돌아오지 않았다.

- `InfantryTower`가 병사를 리스트가 아니라 **자리(slot) 배열**로 들고, 자리마다 대기 시간을 따로 흘린다
  (`_slots` / `_slotTimers`). 동시에 죽으면 동시에 돌아오고, 한 명의 죽음이 다른 자리의 대기를 건드리지 않는다.
- 배치 오프셋을 "현재 인원수"가 아니라 **자리 번호**로 뽑는다. 그전에는 3명 중 1명만 죽어 충원될 때
  살아 있는 병사와 같은 지점에 겹쳐 섰다. 이제 죽은 병사는 원래 서 있던 자리로 돌아온다.
- 충원 대기 시간 15초 -> **10초 (기사단 13초)**. 기사단은 체력 280 + 피해 감소 25%라 회전이 느려도 버틴다.
- `SoldierCount`가 바뀌면 `EnsureSlots`가 자리 수를 맞춘다 (줄어들면 넘치는 자리의 병사를 정리).

### 경로 4루트 구성

손그림 기준 구성이다. **시작 지점 2곳에서 각각 두 방향으로 갈라져 종료 지점 2곳으로 들어가는 총 4개 루트**다.

| 루트 | 시작 | 종료 | 스케치 색 | 길이 |
|---|---|---|---|---|
| A1 | 시작 A (좌상단) | 종료 1 (우상단) | 녹색 | 36.6 |
| A2 | 시작 A (좌상단) | 종료 2 (우하단) | 갈색 | 33.7 |
| B1 | 시작 B (좌하단) | 종료 2 (우하단) | 빨강 | 39.3 |
| B2 | 시작 B (좌하단) | 종료 1 (우상단) | 파랑 | 30.5 |

네 루트는 맵 중앙에서 서로 교차하며 크게 돌아간다. 타워 슬롯은 16곳이고 교차 구간에 배치해
한 슬롯이 여러 루트를 동시에 덮는다 (사거리 가치가 덮는 루트 수에 비례).
중앙 4곳(Slot_11~14)은 네 루트를 모두 사거리 안에 둔다.

씬 배치가 원본이고, 코드의 기본 좌표는 씬에서 다듬은 값을 되받아 둔 것이다.
씬에서 웨이포인트나 슬롯을 옮긴 뒤에는 Stage Command Center의 **"씬 레이아웃 정리"**를 누른다.
위치는 건드리지 않고 이름(P00.., Slot_01..)과 계층 순서만 맞춘 뒤 경로 비주얼을 현재 좌표로 다시 굽는다.

구현:

- 씬 구조는 `Paths/Path_A1`, `Path_B1`, `Path_A2`, `Path_B2`. 각 `PathRoute`는 `RouteId`를 갖고 기즈모를 스케치 색으로 그린다.
- `StageController._paths`가 배열로 들고, `NearestPath(위치)`로 "가장 가까운 루트"를 준다.
  병영 집결지는 이 값으로 정하므로 교차 지점에 세운 병영은 두 루트를 함께 막는다.
- `WaveSpawner`는 고정 구간에서 `RouteWeights` 가중치로, 7웨이브부터는 아키타입 경로 추첨표로 루트를 뽑는다.
- 경로 비주얼은 `PathVisual/Route_XX`로 루트별로 베이크하고, 시작/종료 마커는 좌표가 겹치면 한 번만 찍는다
  (시작 2개 + 종료 2개).
- 씬 검증에 루트 개수 체크와 "슬롯이 길 위에 올라탔는지"(경로에서 1.5 이내) 체크를 추가했다.

씬 반영은 Stage Command Center의 "씬 골격 생성 + 참조 연결"을 한 번 실행하면 된다.
단일 경로 시절의 최상위 `Path` 오브젝트는 셋업이 제거하고, 경로 레이아웃이 바뀌어
길 위에 올라탔거나(1.5 미만) 모든 루트에서 멀어진(6 초과) 슬롯은 기본 좌표로 되돌린다.

남은 조정:

- 웨이브 예산이 루트 4개로 흩어져 지점당 밀도가 1/4이 된다. 물량/슬롯 수 재조정이 필요하다.
- 루트 길이 편차가 최대 21%(29.5 ~ 35.8)다. B2가 가장 짧아 먼저 도착한다.
- 종료 지점이 2곳이 됐지만 도달 처리(`HandleMonsterReachedExit`)는 생명 감소만 하므로 공통으로 뒀다.
  종료별로 다른 처리가 필요해지면 그때 구분한다.

## 미적용

### 중간 보스 스킬 6종 (시트: 중간보스 3종)

짓밟기(저지 유닛 즉사), 견고(광역 피해 감소), 사자 소환(민병 소환), 생명 이전(주변 사망 시 회복),

각각 다른 시스템에 훅이 필요하다 - 짓밟기는 병사 즉사 API, 견고는 `DamageResolver`의 광역 태그 감쇄,
사자 소환은 경로 중간 스폰, 생명 이전은 사망 브로드캐스트, 포격은 타워 무력화 상태,

시트에는 이제 웨이브별 수치까지 확정돼 있다 (짓밟기 5/4.5/4초, 견고 0.4/0.5/0.6, 사자 소환 3/4/6기,
생명 이전 0.015/0.02/0.03, 포격 반경 150 · 6초, 광폭화 4/6/8기). 최종 보스의 "세 부관 스킬을 모두 사용"도 같이 빠져 있다.

- **C13/C14가 병영 타워에는 발동하지 않는다.** 병사 근접 공격은 발사체 경로를 타지 않는다.
  C13은 시트가 조건 칸에 "병영 제외"를 명시해 해소됐고, 카탈로그 설명도 맞췄다.
  C14는 시트가 여전히 "공통"이라 문구상으로만 남아 있다.
- **화염 장판 등 지속 피해로 죽인 적에는 C14가 붙지 않는다.** 발사체 착탄과 죽음의 광선 처치에만 연결돼 있다.
  지속 피해 쪽에 처치 감지 훅을 새로 넣어야 하며, 틱마다 발동하면 폭주 위험이 있어 보류했다.
- **C15는 즉사 판정과 보상 카드 추첨에는 적용되지 않는다** (시트 조건에 명시된 대로).
