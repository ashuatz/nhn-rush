1. 개요

1.1 목적

성향이 서로 다른 가상 유저를 대량으로 만들어 (플레이 인스턴스 수십~수백 판) "실제 유저가 많이 플레이했다면" 상황을 근사한다. 각 가상 유저는 자기 취향대로 빌드를 짜고 카드를 고르며, 도구는 그 결과를 모아 다음 질문에 답한다.

  • 이렇게 빌드를 짠 유저는 어디까지 깨는가? (빌드 유형별 도달 웨이브 / 승률 분포)
  • 어떤 조합이 좋았는가? (타워 구성 x 카드 조합의 성과 랭킹, 카드별 승률 기여)
  • 어떤 조합은 답이 없는가? (사장된 전략 / 반대로 이것만 하면 이기는 지배 전략 탐지)

이 답을 근거로 밸런스 수치 조정을 제안하고, 선택한 항목을 에셋에 적용한다.

1.2 배경

  • 수치 조정 도구(Balance Board)는 이미 있으나, 조정 결과를 검증하는 수단이 수동 플레이뿐이다. 한 판에 약 5분이 걸려 반복 검증이 비현실적이다.
  • 처치/누수/피해 등 핵심 이벤트는 이미 GameLog와 DamageSource를 통해 단일 창구로 흐르고 있어, 수집 훅을 붙이기 좋은 상태다.

3. 시뮬레이션 실행 방식: 동시 실행 + 가속

3.1 동시 실행: 스테이지 리그를 격자로 복제

유저 100명을 한 명씩 순서대로 돌리면 분포가 모이는 데 30분 이상 걸리고, 퍼져나가는 모습을 볼 수도 없다. 대신 StageRig 프리팹(경로+슬롯+컨트롤러+스포너+보상)을 한 씬에 격자로 N개 스폰해 가상 유저 N명이 동시에 플레이하게 한다.

  • 격자 간격은 최대 사거리·스플래시·연쇄 반경의 2배보다 크게 잡는다. 타워/스플래시/병사 탐지가 전부 위치 기반 거리 검사라, 간격만 충분하면 옆 보드를 넘볼 수 없다.
  • 각 리그에는 봇 1개(유저 프로필 1명)가 붙는다. 리그 = 런 = 가상 유저 1명.
  • 동시 인스턴스 수는 성능에 따라 조절한다 (기본 50, 100명 배치면 50 x 2배치). 동시 50개 x 실시간 1~2배 가속이면 유저 100명 분포가 약 5분 안에 나온다.
  • 라이브 분포 뷰: 리그마다 상태 타일(바닥 판)을 하나 두고 드라이버가 남은 생명/승패에 따라 음영을 바꾼다. 씬 뷰에서 격자를 내려다보면 "어떤 유저들이 어디까지 버티는지"가 실시간으로 보인다.
동시 실행의 전제: 전역(static) 상태 정리. 현재 코드는 씬에 스테이지가 1개라고 가정한 전역 참조가 있어 그대로는 보드끼리 상태가 섞인다. 필요한 정리는 5.2에 정리했다. 핵심 3가지: (1) 전투 코드가 카드 효과를 읽는 RewardSystem.Active 전역 참조 → 소유 리그의 인스턴스 참조로 교체, (2) 승리 판정이 세는 전역 몬스터 수 → 자기 리그 소유 몬스터만 세도록 소유 구분 추가, (3) 보상 디밍의 전역 timeScale = 0 → 시뮬레이션 중에는 시간 정지 없이 봇이 즉시 선택. 모두 기계적인 치환이고, 단일 스테이지 플레이 동작은 변하지 않는다.

3.2 가속: 고정 스텝 (captureDeltaTime)

배속을 timeScale로만 올리면 프레임당 deltaTime이 커져 발사체 이동/쿨다운 판정이 실플레이와 달라진다(고배속 왜곡). 대신 Time.captureDeltaTime = 1/30으로 프레임당 게임 시간을 고정하고 vSync를 꺼서 CPU가 내는 만큼 빠르게 프레임을 돌린다.

  • 게임 시간은 매 프레임 정확히 1/30초씩 진행 → 판 사이 결과 편차가 프레임레이트와 무관해진다. 동시 실행으로 fps가 떨어져도 결과는 불변이고 벽시계 시간만 늘어난다.
  • 처리량 = 동시 인스턴스 수 x (fps / 30). 예: 50개 동시 + 60fps = 실시간 대비 100배.

  • 씬 재로드는 쓰지 않는다 (전체가 재시작되므로). 배치 단위로 리그를 일괄 스폰/일괄 파괴한다.
  • 배치는 동기식이다: 전원이 끝나야 다음 배치를 스폰한다. StageController.Awake의 전역 레지스트리 Clear가 배치 시작 시점(몬스터 0마리)에만 일어나게 하기 위함이다. 끝난 리그는 idle 상태라 부하가 거의 없다.
  • 안전장치: 게임 시간 상한(예: 20분)을 넘긴 리그는 강제 종료하고 "타임아웃"으로 기록한다 (승패 판정이 막히는 데이터 오류 탐지용).

3.4 재현성 (시드)와 관전 재생

  • 봇의 의사결정(프로필 샘플링, 슬롯/계열 추첨, 카드 선택)은 봇 전용 System.Random(시드 = baseSeed + userIndex)을 쓴다. 전역 UnityEngine.Random은 동시 실행 시 리그 간 호출 순서가 섞여 재현이 깨지기 때문이다.
  • 게임 쪽 확률(보상 뽑기, 확률 발사)은 전역 Random이라 동시 실행에서는 완전 재현이 안 된다. 대신 관전 재생은 리그 1개만 단독 스폰하므로 이때는 전역 시드 고정으로 거의 재현된다. 분포 분석에는 영향 없다.
  • 리포트에 유저별 시드를 기록하고, 대시보드의 [이 유저 재생]은 해당 시드로 리그 1개를 1배속 단독 실행한다.

4. 가상 유저 (자동 플레이 정책)

4.1 유저 프로필 = 런 1개의 성향값 묶음

런마다 시드에서 유저 프로필을 하나 뽑는다. 프로필은 "이 유저가 어떤 빌드를 짜는 사람인지"를 결정하는 성향값의 묶음이고, 봇은 매 판정 주기(게임 시간 0.5초)마다 이 성향대로 건설/업그레이드/카드 선택을 수행한다. 같은 시드는 같은 유저를 재현한다.

성향값의미샘플링
계열 선호 가중치궁병/마도/포병/보병 4계열에 대한 투자 비율. 건설 시 가중 추첨디리클레풍 랜덤 (몰빵~균형 사이)
업그레이드 성향골드가 생겼을 때 신규 건설 vs 기존 강화 중 무엇을 선호하는지0.0 ~ 1.0
저축 성향즉시 소비 vs 다음 웨이브까지 골드 저축 (조기소환/이자 카드와 상호작용)0.0 ~ 1.0
조기소환 성향필드가 비면 조기소환을 얼마나 적극적으로 누르는지안 함 / 가끔 / 항상
카드 취향제시 카드 중 선택 기준: 랜덤 / 등급 우선 / 자기 주력 계열 관련 우선 / 스킵 선호4유형 중 추첨
프리셋도 유지한다. 랜덤 프로필 외에 고정 프리셋(균형, 단일 계열 몰빵 4종, 올스킵)을 배치에 일정 비율 섞을 수 있다. 프리셋은 "기준선"이 되어 랜덤 유저들의 성과를 해석하는 축이 된다. 특정 조합을 정확히 재현하고 싶으면 빌드오더 스크립트(슬롯+계열+레벨 순서 고정)를 프로필 대신 지정한다.

4.2 실행 방식

  • 건설 실행은 BuildMenu에서 추출한 공용 헬퍼 TowerBuilder.TryBuild(slot, towerData, stage)를 호출한다.
  • 슬롯 선택은 "경로까지의 최단 거리" 정렬을 기본으로 하되, 프로필의 계열 선호에 따라 사거리가 긴 계열은 후열 슬롯도 허용한다 (런 시작 시 TowerSlot 전수 스캔 1회로 베이크).
  • 카드 선택은 RewardSystem.OfferChanged 구독 후 공개 API(Pick / Reroll / Skip)를 그대로 호출한다. 다시뽑기는 카드 취향과 맞는 카드가 없을 때 사용한다.

5.2 게임 코드 변경 지점

동시 실행 전제(3.1) 때문에 "씬에 스테이지 1개" 가정의 전역 참조를 소유 참조로 바꾸는 정리가 들어간다. 전부 기계적 치환이며 단일 스테이지 플레이의 동작은 변하지 않는다.

대상변경규모
RewardSystem.Active 전역 참조전투 코드(Tower/Soldier/Monster/Projectile/DamageResolver 등)가 카드 효과를 읽는 static 쿼리 약 28곳을 소유 리그의 RewardSystem 인스턴스 참조로 교체. Tower는 Stage를 이미 들고 있고, Monster/Soldier/Projectile에는 초기화 시 참조를 내려준다 치환 28곳
MonsterRegistry / Soldier 레지스트리몬스터/병사에 소유 리그 키를 달고, StageController.CheckVictory는 자기 소유 몬스터만 센다. 위치 기반 탐색은 격자 간격으로 격리되므로 그대로 둔다 (동시 수를 늘려 느려지면 리그별 분리로 최적화) 소유 키

6.1 조합 분석 방법

  • 빌드 유형 분류: 최종 투자 골드의 계열별 비중으로 유저를 분류한다. 1개 계열이 70% 이상이면 "몰빵", 상위 2개 계열 합이 80% 이상이면 "듀오(계열A+계열B)", 그 외 "혼합". 복잡한 군집화 없이 규칙 기반으로 충분하다.
  • 유형별 성과: 유형마다 승률, 평균 도달 웨이브, 표본 수를 함께 표기한다. 표본 5명 미만 유형은 회색 처리(신뢰 불가).
  • 카드별 승률 기여: 카드 K를 "픽한 유저 승률 - 픽하지 않은 유저 승률"로 정렬한다. 엄밀한 인과가 아니라 탐색용 신호이며, 표본 수를 함께 보여 과신을 막는다.
  • 상세 보기: 상위/하위 조합을 클릭하면 해당 유저의 빌드 오더 타임라인과 카드 목록을 보여주고, [이 유저 재생] 버튼으로 같은 시드를 1배속 관전 재생한다.

6.2 공통 규칙

  • 배치 실행 중에는 [1]의 입력을 잠그고 진행 상태만 갱신한다. 중단 시 완료된 런까지만 리포트에 남긴다.
  • 대시보드의 시각 요소(분포/히트맵)는 셀 음영과 막대 길이만 쓰는 단순 표현으로 한다 (그래프 라이브러리 불필요).
  • 구현 시 unity-editor-tool-gotchas, Unity-Editor-Layout-SKILL 스킬을 선행 확인한다 (플레이 모드 전환 시 윈도우 상태 보존 등).

7. 자동 밸런싱

7.1 목표 지표 (기본값, 윈도우에서 수정 가능)

전체 승률 (랜덤 유저 집단)50 ~ 70%평범하게 하면 이길 수도 질 수도 있는 난이도
기준선(균형 프리셋) 승률60 ~ 80%합리적으로 하면 대체로 이기는 난이도

빌드 유형 간 승률 격차최고-최저 50%p 이하지배 전략 / 사장 전략 방지 (조합 분석과 직결)

7.2 2단계 접근: 자동 탐색 + 제안

배치 결과
→
1단계: 전역 배율 자동 탐색
→
승률 밴드 진입
→
2단계: 룰 기반 제안 생성
→
사람이 검토 후 선택 적용
  • 1단계 (자동): 조정 노브를 DifficultyPreset.EnemyHpMultiplier 하나로 한정한 1차원 이분 탐색. 승률이 밴드보다 높으면 배율 상향, 낮으면 하향. 배치 실행-측정-조정을 최대 5회 반복하고 이력을 로그로 남긴다.
  • 2단계 (제안): 다차원 수치(몬스터 종별 스탯, 타워 레벨 스탯, 카드 수치)는 자동 변경하지 않는다. 룰에 걸린 항목을 근거와 함께 제안 목록으로 출력하고, 사람이 체크한 항목만 적용한다.
제안 룰 (초기 세트)제안 내용
사장 전략: 특정 빌드 유형 승률 < 25% (표본 충분 시)주력 계열의 Damage 상향 또는 Cost 하향 후보 제시 (몰빵 유형이면 해당 계열 단독 성능 문제로 해석)
지배 전략: 특정 빌드 유형 승률 > 90% + 전체 평균과 30%p 이상 격차주력 계열 Damage 하향 또는 Cost 상향 후보 제시
카드 승률 기여 최상위/최하위 (표본 충분 시)해당 카드 Value/확률 하향/상향 후보 제시 (Balance Board 항목으로 링크)
웨이브 W 누수 스파이크 발생해당 웨이브 누수 기여 1위 몬스터의 HP 또는 MoveSpeed 10% 하향
계열 피해 점유율 < 10% (혼합 유저 기준)해당 계열 Damage 10% 상향 (또는 Cost 10% 하향)
몬스터 종 처치율 > 98% + 누수 기여 0위협 없음: HP 상향 또는 GoldReward 하향 후보로 표기
자동 적용 범위를 좁게 유지하는 이유. 다차원 자동 최적화는 판 수가 부족하면 노이즈에 과적합되고, 해커톤 일정에서 검증할 시간도 없다. "전역 1개 노브만 자동, 나머지는 근거 있는 제안"이 비용 대비 효과가 가장 크다. 적용은 Balance Board와 동일하게 에셋 SetDirty + 저장으로 처리해 되돌리기(시트 기본값 초기화)와 호환된다.

8. 기술 제약과 리스크

항목내용 / 대응
고정 스텝과 실플레이의 차이실플레이는 가변 dt라 미세하게 다르다. 30fps 고정은 실기기 하한과 유사해 밸런스 판단에는 충분하다고 본다. 필요 시 스텝을 1/60로 낮춰 교차 확인.
동시 실행 시 보드 간 간섭격자 간격을 최대 사거리/스플래시/연쇄 반경의 2배 이상으로 강제하고, 배치 시작 시 간섭 검증(간격 < 상한이면 실행 거부)을 넣는다. 전역 상태는 5.2의 정리로 차단.
동시 수를 늘렸을 때 성능전역 레지스트리 순회(타워 타겟팅)가 몬스터 총수에 비례해 무거워진다. 동시 인스턴스 수로 조절하고, 부족하면 레지스트리를 리그별로 분리한다. fps가 떨어져도 고정 스텝이라 결과는 불변.
봇과 사람의 실력 차봇은 "합리적 기준선"이지 사람 플레이가 아니다. 절대 난이도가 아니라 수치 변경 전후의 상대 비교에 주로 사용한다.
보상 카드 54종 조합 분산런 수가 적으면 카드 운이 승률을 흔든다. 기본 100런 + 시드 고정으로 완화하고, 올스킵 프리셋으로 카드 없는 기준선을 따로 잰다. 조합 분석은 표본 수를 항상 함께 표기한다.
Instantiate/Destroy 부하가속 중 GC 스파이크로 fps가 떨어질 수 있으나 게임 시간은 고정 스텝이라 결과는 불변, 소요 시간만 늘어난다. 허용.
플레이 모드 중 코드 리로드배치 중 스크립트 저장 시 도메인 리로드로 배치가 죽는다. 배치 시작 시 EditorApplication.LockReloadAssemblies로 잠그고 종료 시 해제.
타임아웃 런이동속도 0 보정 등으로 이론상 없어야 하나, 발생 시 시드와 함께 별도 표기해 버그 리포트로 활용.
