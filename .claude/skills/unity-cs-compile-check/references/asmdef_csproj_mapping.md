# Assembly Definition to .csproj Mapping Reference

## Unity Assembly System Overview

Unity uses Assembly Definition files (`.asmdef`) to organize C# code into separate assemblies. Each `.asmdef` corresponds to a `.csproj` file generated by Unity at the project root.

## Mapping Rules

### Direct Name Mapping
The `.asmdef` file's `"name"` field maps directly to a `.csproj` filename:
- `MyGame.Core.asmdef` with `"name": "MyGame.Core"` -> `MyGame.Core.csproj`
- `MyGame.Editor.asmdef` with `"name": "MyGame.Editor"` -> `MyGame.Editor.csproj`

### Default Assemblies (No .asmdef)
Files NOT covered by any `.asmdef` fall into Unity's default assemblies:
- `Assets/` scripts -> `Assembly-CSharp.csproj`
- `Assets/Editor/` scripts -> `Assembly-CSharp-Editor.csproj`
- `Assets/Plugins/` scripts -> `Assembly-CSharp-firstpass.csproj`
- `Assets/Plugins/Editor/` scripts -> `Assembly-CSharp-Editor-firstpass.csproj`

### .asmdef Scope Rules
- A `.asmdef` file covers all `.cs` files in its directory and all subdirectories
- UNLESS a subdirectory contains its own `.asmdef` (which starts a new assembly)
- The nearest `.asmdef` walking up from the `.cs` file determines the assembly

### .csproj Location
Unity generates all `.csproj` files at the **project root** (same level as `Assets/`, `Packages/`, `ProjectSettings/`).

## .asmdef JSON Structure

```json
{
    "name": "MyGame.Core",
    "rootNamespace": "MyGame.Core",
    "references": [
        "Unity.TextMeshPro",
        "UniTask"
    ],
    "includePlatforms": [],
    "excludePlatforms": [],
    "allowUnsafeCode": false,
    "overrideReferences": false,
    "precompiledReferences": [],
    "autoReferenced": true,
    "defineConstraints": [],
    "versionDefines": [],
    "noEngineReferences": false
}
```

## Common dotnet build Issues

### Missing Unity Engine References
Unity's `.csproj` files reference Unity engine DLLs. If `dotnet build` fails with missing UnityEngine references, the Unity Editor must have generated the `.csproj` with correct paths. Ensure:
1. Unity Editor has been opened for the project at least once
2. "Preferences > External Tools > Generate .csproj files" is enabled
3. The `.csproj` files are up-to-date (regenerate via Unity Editor if needed)

### Target Framework Mismatch
Unity projects target `netstandard2.1` or `net48` depending on the API compatibility level. The `dotnet build` command uses the target specified in the `.csproj`.
